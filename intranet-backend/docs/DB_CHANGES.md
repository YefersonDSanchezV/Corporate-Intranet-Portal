## 2. POR QUÉ se cambió

- **Las migraciones estaban vacías.** `V1__baseline.sql` contenía solo dos comentarios y `V2`–`V5` eran archivos de 0 bytes. No existía DDL versionado (`CREATE TYPE/TABLE/INDEX`) del esquema.
- **El esquema real solo vivía en la base de datos** (ver hallazgo #1 de `docs/DATABASE.md`). El backend dependía de que la BD ya tuviera las 29 tablas documentadas en el catálogo, pero no había ninguna definición reproducible para entornos nuevos.
- **No había capa de datos.** Sin DDL versionado, las entidades JPA/API implementadas en esta fase no tenían un esquema de referencia verificable ni un medio de crear la BD en desarrollo/CI.

## 3. PARA QUÉ se realizó

- **Dar soporte reproducible a las entidades/API implementadas** (dominios `asi-`, `com-`, `gen-`, `innov-`): usuarios, solicitudes de acceso, auditoría, anuncios, tareas, logros, roles/permisos, directorio, módulos/sitios, archivos, formatos de contingencia y enlaces de innovación.
- **Documentar en código los tipos `USER-DEFINED`** (los 4 enums no tenían DDL: hallazgo #7 de `docs/DATABASE.md`). Se definen con los valores estándar de la UI/plan (§5.3 del plan de implementación).
- **Permitir arrancar una BD nueva desde cero** (`mvn flyway:migrate` en un entorno vacío) sin depender del esquema físico preexistente.

## 4. QUÉ se realizó exactamente

Reescritura completa de `V1__baseline.sql`:

- **4 `CREATE TYPE`** de enumerados, con nombres entre comillas que coinciden con los enums Java de Hibernate (`EstadoAnuncio`, `EstadoTarea`, `PrioridadTarea`, `EstadoSolicitud`) para el mapeo `@JdbcTypeCode(SqlTypes.NAMED_ENUM)`:
  - `"EstadoAnuncio"` ('PENDIENTE','PUBLICADO','RECHAZADO','VENCIDO')
  - `"EstadoTarea"` ('PENDIENTE','EN_PROGRESO','COMPLETADA')
  - `"PrioridadTarea"` ('ALTA','MEDIA','BAJA')
  - `"EstadoSolicitud"` ('PENDIENTE','APROBADA','RECHAZADA')
- **28 tablas de negocio** (todas las de `docs/DATABASE.md`; la 29.ª es `flyway_schema_history`, estándar de Flyway), cada una con:
  - `oid integer GENERATED BY DEFAULT AS IDENTITY` como PK (convención del catálogo).
  - Columnas en `snake_case` con prefijo de tabla según `docs/DATABASE.md`.
  - Tipos `timestamp` (sin time zone) para fechas, `date` para `genusufecnam`, `bigint` para identificaciones/tamaño.
  - Columnas `text` para descripciones largas y valores de auditoría.
  - **FKs** nombradas por el nombre de la tabla padre, con la excepción documentada `gensitredireccion.modulo → genmodulo`.
- **Índices** sobre todas las columnas foráneas y los campos de consulta frecuente (username/correo de usuario, estados de anuncios/tareas/solicitudes, directorio por área/piso, puentes de archivos, etc.).
- **Sin sentencias de seed** (no eran necesarias; evita imponer datos o credenciales).

## 5. Impacto en la base existente

- **BD real (ya con esquema):** `V1` **NO se vuelve a ejecutar**. La configuración ya usa `flyway.baseline-on-migrate: true` y `baseline-version: 1`, así que Flyway marca el baseline y deja intacto el esquema existente. El `ddl-auto: validate` de JPA valida las entidades contra el esquema real.
- **Riesgo conocido (enums):** si en la BD real los tipos `USER-DEFINED` se crearon con otro nombre o minúsculas (p. ej. `estadoanuncio`), la validación de JPA (`validate`) fallará al arrancar. Mitigación: renombrar los tipos en la BD real a los nombres de los enums Java (`EstadoAnuncio`, `EstadoTarea`, `PrioridadTarea`, `EstadoSolicitud`) o ajustar el `@JdbcTypeCode`/la migración. Se requiere acceso de lectura/DDL a `intraicvc` (192.168.3.121:5432) para confirmar.
- **Riesgo conocido (identity):** si la BD real usa secuencias externas en `oid` (en lugar de `IDENTITY`), el `GenerationType.IDENTITY` de JPA podría no generar valores al insertar. Mitigación: verificar el DDL real; en ese caso usar `GenerationType.SEQUENCE` o adaptar V1.
- **Entornos nuevos:** `V1` crea el esquema completo desde cero y queda registrada en `flyway_schema_history`; las migraciones `V2`–`V5` vacías se aplican sin efecto.

## 6. Cómo verificar

```bash
# Entorno con PostgreSQL disponible
./mvnw spring-boot:run          # aplica/marca baseline y valida entidades (ddl-auto: validate)
./mvnw flyway:info              # muestra el estado de las migraciones
```
